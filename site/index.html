THREE STEPS TO A CALMER QUEUE

Your Mac.
Your pull requests.

Mergeport talks to GitHub’s API with your own account. There’s nothing to self-host and no server in between.

Read how sign-in works ↗

  1. Give it a home on your Mac.

    Download the DMG, open it, and drag Mergeport into the Applications folder. Then open it from Applications. Requires macOS 14 or later on Apple Silicon.

  2. Connect GitHub.

    Click Connect GitHub, enter the short code in your normal browser, and authorize. Your existing GitHub session and password manager just work. Approve SSO for organizations with private repositories.

  3. Make it yours.

    Follow extra repositories, set up branch and ticket grouping, and optionally connect Linear. Then open a PR and review it right there.

THE SMALL PRINT, NOT SO SMALL

Good to know.

Is it really free?

Yes. Mergeport is free and open source under the MIT license. No subscription, trial timer, or paid tier. Browse the source, report an issue, or make it your own on GitHub.

What access does it need?

Mergeport asks GitHub for the repo, read:org and notifications scopes. It only writes when you ask it to: comments, reviews, resolving threads, draft changes, reviewers, labels and merging. GitHub still enforces your permissions and branch rules.

The OAuth token is stored in macOS Keychain and is only sent to GitHub’s API. No password or browser cookie is copied. Signing out removes the token, cached PRs and local drafts; you can also revoke access in GitHub’s authorized apps.

Which Macs and accounts are supported?

Release builds support Apple Silicon Macs running macOS 14 or later. Mergeport works with one GitHub.com account, including organization repositories you can access. GitHub Enterprise Server is not supported yet.

Does it replace GitHub in the browser?

For day-to-day reviewing, mostly. Conversations, diffs, inline comments, checks, reviewers, labels and merging are native. A few GitHub-only extras—like reactions and Copilot session widgets—aren’t reproduced; every PR opens on GitHub with one click (⌘↩ in quick open).

How do updates work?

Official releases are signed and notarized. Sparkle checks for signed updates daily while the app is running, and installation always needs your approval. You can also use Check for Updates or turn off automatic checks in Settings.
